## 二、各章节口播脚本与分工

### 1 号 · 项目背景 + 架构（1 分钟）

- **定位**：本项目是面向城市道路照明的**智慧路灯物联网管理平台**，代号「灯廊」。
- **解决什么问题**：传统路灯靠固定时间/人工巡检，能耗高、响应慢、故障难发现。
- **五层架构**（自上而下）：

  ```
  前端控制台(灯廊) → 后端规则引擎(Spring Boot) → 数据库(PostgreSQL)
        ⇅ MQTT(EMQX) ⇅
        板端(BearPi 路灯，光照传感器 + LED)
  ```

- **一句话主线**：硬件采集光照 → MQTT 上报 → 云端阈值判定自动开关灯 → 告警 → 前端实时可视。

---

### 2 号 · 硬件采集（1 分钟）

- **板端**：BearPi-HM Nano（Hi3861，WiFi 2.4G）。
- **传感器**：BH1750 数字光照传感器，采集环境光照强度（lux）。
- **执行器**：GPIO 驱动 LED，模拟路灯本体。
- **动作演示**：遮光/打光 → 光照数值实时变化；说明采样周期性上报。

---

### 3 号 · MQTT 通信（1 分钟）

- **Broker**：EMQX（Docker 5.8）。
- **Topic 约定**：`smart-light/{deviceSn}/…`
  - 上行：`/light`（光照）、`/status`（状态回传）、`/alarm`（告警）
  - 下行：`/command`（AUTO_ON/AUTO_OFF/MANUAL_*）
- **工程质量点**：数据上行 QoS 0（at most once）、指令/告警 QoS 1（at least once）；非阻塞消息路由。

---

### 4 号 · 后端 + 数据库（1 分钟）

- **后端**：Spring Boot 3.5 + MyBatis-Plus。
- **核心能力**：
  - REST API：设备/光照/告警/阈值/控制日志/用户认证（JWT）
  - WebSocket(STOMP) 实时推送
  - 定时任务 `HeartbeatCheckTask`：每 30s 扫描心跳超时 → 判离线
- **数据库**：PostgreSQL（pgvector 扩展）+ 正交表设计：`devices`、`light_readings`、`alarm_logs`、`control_logs`、`threshold_config`、`users`。
- **内存里强调**：脏数据可清理、控制日志可审计。

---

### 5 号 · 自动控制 + 告警（1 分钟）

- **自动控制**：光照 < 开灯阈值 → `AUTO_ON`；光照 > 关灯阈值 → `AUTO_OFF`；滞回双阈值防抖动。
- **阈值可配**：Web「阈值」页改 `lightThresholdOn/Off`、`heartbeatTimeout`。
- **告警**：离线告警、执行失败告警；告警列表可按类型/状态筛选，并支持"处理"闭环。
- **动作演示**：遮光 → 自动开灯；拔掉设备 → 超时离线告警弹出。

---

### 6 号 · 前端展示 + 实时交互（1 分钟）

- **技术栈**：Vue3 + TypeScript + Vite，布局为「灯廊」控制台。
- **页面**：总览(Dashboard) / 设备 / 光照监测(趋势折线) / 告警 / 阈值 / 控制日志 / 登录。
- **实时性**：订阅 WebSocket，光照、开关状态、告警一处数据变化全屏联动刷新。
- **动作演示**：切换阈值 → 观察趋势图/仪表数字实时刷新。

---

### 1 号 · 完整闭环总结 + 演示（1 分钟）

- **串起一句话**：从 BH1750 采到一份 lux → 走上 MQTT → 后端判定 → 下发 command → LED 亮/灭 → 状态回传 → 控制台看到 + 可能触发告警，这就是本项目最小但完整的 IoT 闭环。
- **真机/控制台演示**：实时曲线、手动开灯、阈值自动、告警处理。
- **诚实边界**：当前为局域网/本地部署；Agent(RAG) 为辅助层且不无确认下发 MQTT。
