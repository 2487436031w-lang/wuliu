# 智慧路灯「灯廊」· 迭代 / 创新 / Agent 规划（答辩补充）

> 承接 [`TECH-STACK-AND-DESIGN.md`](TECH-STACK-AND-DESIGN.md)。  
> 原则：**IoT 闭环是脊柱**；Agent 是应用层辅助模块；LLM **不得**无人确认自动下发 MQTT（见根目录 `CONTEXT.md`）。

## 1. 现实场景与岗位工作

| 角色 | 真实工作 | 当前系统覆盖 | 下一阶段缺口 |
|------|----------|--------------|--------------|
| 市政值班 | 看离线/异常、处理告警、交接班 | 告警列表、处理、在线状态 | 值班待办、告警归因、态势一句话摘要 |
| 路灯管理员 | 改策略、远程干预、留痕审计 | 全局阈值、手动开关、控制日志 | 设备/分组策略、指令是否真正执行 |
| 演示/答辩 | 讲清闭环与工程难点 | 真机 + Docker + 文档 | 可选运维助手页；创新点可视化 |

## 2. MoSCoW 切分

### Must（下一迭代优先，运维实用）

| ID | 功能 | 验收要点 |
|----|------|----------|
| M1 | **指令闭环确认** | 下发 command 记 PENDING；收到匹配 status 记 SUCCESS；超时 → 执行失败类告警 |
| M2 | **告警类型加深** | 至少：`OFFLINE`、上报停滞、指令无回执；列表可按类型筛选 |
| M3 | **值班总览待办** | Dashboard：活跃告警、离线列表、今日 AUTO 开关次数（可用现有统计接口聚合） |

### Should（强答辩 / 仍可交付）

| ID | 功能 | 验收要点 |
|----|------|----------|
| S1 | **设备级或策略组阈值** | 无覆盖时回退全局；改阈值后自动策略立即按新规则 |
| S2 | **批量开关（按筛选）** | 对筛选结果循环 `switch` 或 batch API；控制日志可追溯 |
| S3 | **运维助手页（薄 Agent）** | 见 §4；大模型不可用时模板降级仍可演示 |

### Could（差异化创新，二选一做深）

| ID | 功能 | 答辩价值 |
|----|------|----------|
| C1 | **期望 vs 实际一致性面板** | 云端目标态与板端 status 不一致 → 故障态，强化「可观测」 |
| C2 | **阈值回放沙箱** | 用历史 lux 回放「若改阈值会触发几次」；零新硬件 |
| C3 | **时段策略 + 模拟时钟** | 傍晚/正午策略；室内演示用模拟时钟 |

### Won't（本阶段明确不做）

- 固件 OTA、公有云生产部署、摄像头、真 GIS 地图必选  
- Agent **无人确认**直接控灯  
- 以「加了大模型」替代物联网主线叙事

## 3. 创新点怎么讲（服务 IoT，不飘）

推荐答辩主创新 **选 1 个** + 工程硬点（MQTT 非阻塞）固定保留：

1. **滞回阈值可视化**：lux 曲线 + on/off 双阈值带，讲清防抖动。  
2. **一致性面板（C1）** 或 **回放沙箱（C2）**：证明平台侧「管理价值」，不靠新传感器。  

叙事顺序：场景 → 五层架构 → 闭环演示 → **一个**工程难点 →（可选）创新可视化 ≤1 分钟 → Agent ≤1 分钟 → 局限与路线图。

## 4. 真正实用的 Agent（运维副驾驶）

### 4.1 定位

| 层 | 职责 | 谁执行 |
|----|------|--------|
| 确定层 | 阈值自动开关、心跳离线 | 规则引擎（已有） |
| 辅助层 | 解释、摘要、建议 | Agent / RAG |
| 执行层 | 开关灯、改阈值 | 人工确认或规则；**不**由 LLM 直连 command |

### 4.2 最小可演示能力（建议 MVP）

后端已有：`POST /knowledge-chunks/chat`、`/rag`、`/import`（前端待接）。

| 技能按钮 | 输入 | 输出 | 降级（无 LLM） |
|----------|------|------|----------------|
| **态势摘要** | 在线数、离线、活跃告警、最近 lux | 3–5 句交接班摘要 | 模板填空同一结构 |
| **解释本条告警** | alarmId + 设备最近 heartbeat/lux/control | 可能原因 + 建议检查项 | 按 alarmType 固定话术 |
| **阈值建议（不自动写）** | 近 24h lux 分布 | 建议 on/off + 理由；需 ADMIN 确认才写入 | 分位数统计 + 固定文案 |

知识库优先导入：`API文档.md`、`HARDWARE-E2E.md`、本目录答辩 FAQ、联调变更说明。

### 4.3 硬约束（答辩必答）

- Agent **只读**业务数据 + 知识库；产出 draft。  
- 任何 MQTT 下行须人点确认或走规则引擎。  
- 演示不依赖外网：密钥缺失时走模板降级，仍完成「模块存在」叙事。
