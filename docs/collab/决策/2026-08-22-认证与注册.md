# 决策：认证与注册

| 字段 | 内容 |
|------|------|
| 日期 | 2026-08-22 |
| 状态 | **已确认（建议）** — 待组长书面点头后改 `已落地` |
| 影响部门 | 前端、后端、产品 |
| 发起 | 前端 / 协作区 |

## 结论

| 阶段 | 是否做「用户自助注册」 | 账号从哪来 |
|------|------------------------|------------|
| **MVP** | **否** | 预置演示账号（按五角色）；或管理员在库里插入 |
| **进阶** | 可选 | `POST /api/auth/register` 仅 `admin` 可调，或后台「创建用户」页 |
| **最终 / 答辩** | 按老师是否要求「用户管理」故事 | 若无独立用户故事，保持预置即可 |

## 理由

1. 老师 11 条用户故事**没有**「游客注册」；主线是绑定 → 追踪 → 告警 → 调度。  
2. 现有 [`接口文档.md`](../../../接口文档.md) 认证节只有 `login` / `logout`，**无 register**。  
3. 实训演示要「选角色进舱」；开放注册会增加鉴权、审核、脏数据，挡主链路。  
4. 前端已要求：切换角色必须重新输入用户名密码（会话不可免密改角色）。

## 对各部门的含义

| 部门 | 要做 | 不做（MVP） |
|------|------|-------------|
| 前端 | 登录页；空账号拦截；可选「演示账号说明」文案 | 注册页、注册接口调用 |
| 后端 | `login`/`logout`；种子用户（五角色） | 开放 `register`（除非进阶 CR） |
| 产品 | 演示脚本写清五个账号 | 把注册写进 Must |
