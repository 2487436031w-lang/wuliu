# 决策：接口是否继续扩展

| 字段 | 内容 |
|------|------|
| 日期 | 2026-08-22 |
| 状态 | **已确认（建议）** |
| 影响部门 | 全员 |
| 发起 | 前端 / 协作区 |

## 结论

**会添加其他接口**，但是：

1. **只按功能分期加**（MVP → 进阶 → 最终），不在联调周口头加字段。  
2. **每加一条**：改 `接口文档.md` + `docs/contracts/` + `changelog` + 本协作区知会。  
3. **前端当前 Mock** 已覆盖 MVP REST/WS 形状；真后端对齐同一清单即可。

## 分期接口清单（规划）

### MVP（Must — 已在接口文档）

| 域 | 接口 | 备注 |
|----|------|------|
| 认证 | login / logout | **无 register** |
| 车辆 | CRUD `/api/vehicles` | |
| 货物 | list/create/detail `/api/cargos` | |
| 绑定 | bindings | |
| 位置 | positions / position / track / eta | |
| 告警 | list / detail / resolve | |
| 调度 | POST/GET `/api/dispatch` | |
| 司机状态 | `POST /api/cargos/{id}/status` | |
| WS | `/ws/positions` `/ws/alarms` | |
| MQTT | gps / alarm / status / dispatch | 端侧+后端；与 contracts/mqtt 命名待统一 |

### 进阶（Should — 计划加）

| 域 | 拟议接口 | 消费方 |
|----|----------|--------|
| AI 研判 | `GET/POST /api/alarms/{id}/judgment` | 调度/货主详情 |
| 调度副驾 | `POST /api/dispatch/draft` → 人确认后再 `dispatch` | 调度 |
| 运单叙事 | `GET /api/cargos/{id}/narrative` | 货主 |
| 对话 | `/api/chat`（接口文档已有，可延后实现） | 货主 |
| 用户管理 | admin 创建用户 **或** register（若决策放开） | 管理 |

### 最终（Could）

| 域 | 拟议 | 备注 |
|----|------|------|
| 审计 | 指令/研判审计列表 | 答辩加分 |
| 双模定位配置 | 设备 `source=gps\|sim` 查询/切换 | 与端侧一致 |
| 多车模拟灌数 | 管理端「注入模拟轨迹」 | 演示用，可仅后端工具 |

## 明确不做（除非 CR）

- 开放公网注册 + 邮箱验证码  
- LLM **无人确认**自动狂发 MQTT  
- 用 LLM 替代阈值告警  

## 命名债（需三方确认）

| 来源 | Topic / 路径 | 问题 |
|------|--------------|------|
| `接口文档.md` | `device/{id}/gps` | |
| `docs/contracts/mqtt.md` | `logistics/{id}/telemetry` | **不一致** |
| 路灯参考仓 | `smart-light/{sn}/…` | 仅参考，不进物流 |

→ 请后端+端侧在收件箱回复选一套，升 `frozen` 前统一。

## 前端对后端的承诺

- Mock Adapter 与 `接口文档.md` 字段同形；切 `VITE_API_MODE=http` 时不改页面只换 Adapter。  
- 新增进阶接口时，前端开独立页/模块，不堵 MVP 演示门。
