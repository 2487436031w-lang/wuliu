## 1. 做了什么

### 1.1 阈值可按编组 / 单设备单独配置（S1）

| 项 | 说明 |
|----|------|
| 优先级 | **设备覆盖 > 编组覆盖 > 全局** `threshold_config` |
| 心跳超时 | 仍仅全局生效 |
| 表 | `threshold_overrides`（`DEVICE` \| `GROUP`） |
| 自动开关 | `checkAndAutoControl` 读该设备的**生效阈值** |
| API | `GET/PUT /threshold-config`（全局）<br>`GET/PUT/DELETE /threshold-config/overrides`<br>`GET /threshold-config/effective/{deviceId}` |
| 前端 | 阈值页：左全局、右覆盖列表；支持编组/单设备保存与删除 |

迁移：`smart-street-light-master/sql/migrations/V20260825_threshold_override.sql`  
（已并入 `schema.sql`，新库初始化即有表）

### 1.2 光照页：总体 / 编组 / 单灯

- 顶部切换：**总体**（全网按分钟平均）· **编组** · **单灯**
- 趋势接口：`GET /light-readings/trend` 的 `deviceId` / `groupName` 均可选；都不传 = 全体
- 聚合方式：先按设备求该分钟均值，再对设备均值取平均（避免上报频率不齐拉偏）
- 顶部阈值横幅随当前视图显示**生效来源**，并跳转到阈值页对应范围（带 query）

### 1.3 设备页：已分组 / 未分组切换

- 不再上下并排双区（易把「已分组」挤成空白）
- 工具栏 **已分组 | 未分组** 互斥切换，各自占满下方区域
- 默认进入「已分组」；空一侧时自动落到有数据的一侧

### 1.4 总体亮度 1000+ 尖峰修复

| 原因 | 处理 |
|------|------|
| 编队模拟中午 lux 公式突跳到 ~1100 | `mqtt-fleet-loop.sh` 改为平滑曲线，峰值约 **380–420** |
| 真机约 400、模拟 1100，分钟稀疏时总体来回跳 | 见上 + 按设备再平均 |
| 演示数据日间峰值过高 | `test-data.sql` 峰值下调到约 400 |

编队模拟启动：

```powershell
cd smart-street-light-master
powershell -ExecutionPolicy Bypass -File scripts\mqtt-simulate-fleet.ps1
# 停止：... -Stop
```
