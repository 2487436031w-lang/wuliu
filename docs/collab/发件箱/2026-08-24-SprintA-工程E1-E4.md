# Sprint A 工程迭代 · E1–E4 实现说明

> 发件箱 · 2026-08-24  
> 对应任务：M1 指令闭环、M2 告警加深、M3 值班待办

## 1. 数据库迁移（必做）

已有 PostgreSQL 库需执行：

```powershell
# Docker PG 默认端口 5433
Get-Content smart-street-light-master\sql\migrations\V20260824_control_logs_execution.sql |
  docker exec -i <pg容器名> psql -U postgres -d smart-street-light
```

或本地 psql 连库执行同文件。新装库用更新后的 `schema.sql` 即可。

新增字段：

- `control_logs.execution_status` — `PENDING` | `SUCCESS` | `TIMEOUT`
- `control_logs.expected_status` — `ON` | `OFF`

## 2. 后端改动摘要

| 模块 | 行为 |
|------|------|
| `ControlLogsServiceImpl` | 下发指令记 `PENDING`；status 回传匹配 → `SUCCESS` |
| `DevicesServiceImpl.switchDevice` | 手动开关走 pending |
| `LightReadingsServiceImpl` | AUTO_ON/OFF 走 pending |
| `DevicesServiceImpl.updateDeviceStatus` | 板端回传确认 pending（不再写 STATUS_CALLBACK 日志） |
| `CommandTimeoutCheckTask` | 15s 扫描，30s 无回执 → `TIMEOUT` + `COMMAND_TIMEOUT` 告警 |
| `ControlLogsController` | 新增查询参数 `source` |

## 3. 前端改动摘要

| 页面 | 内容 |
|------|------|
| 控制日志 | 展示执行状态徽章 + 期望 status |
| 告警 | 按类型筛选（含 COMMAND_TIMEOUT） |
| 总览 Dashboard | 「值班待办」：活跃告警、今日 AUTO 次数、离线设备列表 |

## 4. 验收步骤

1. 启动 Docker + 后端 + 前端  
2. 手动开关 → 控制日志显示「等待回执」  
3. 板端回传 status（或 MQTT simulate）→ 变为「已确认」  
4. 断开板端订阅，再开关 → 约 30s 内出现 `COMMAND_TIMEOUT` 告警  
5. Dashboard 待办三块数据正确  

## 5. Agent 组可对接

- 告警类型 `COMMAND_TIMEOUT` 已可用  
- `GET /control-logs?source=AUTO` 可统计自动开关  
- 控制日志字段 `executionStatus` / `expectedStatus` 已出现在 API 响应
