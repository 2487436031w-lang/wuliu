# 智慧物流 — 概念设计（对齐老师清单 × 小熊派能力）

> **主参考：** `Offered Topics/02_智慧物流_基本功能清单（可选,杜邦线）(1).md`  
> **硬件基准：** BearPi + E53-ST1（L80-R GPS、无源蜂鸣器、LED）；文件名已提示可用杜邦线扩展  
> **方法：** 先还原老师核心期望 → 再映射板端能力 → 再做个性化实现设计  
> **Skill：** `iot-mvp-prd` / `iot-project-design-defense`

---

## 0. 设计原则（本轮纠正）

1. **老师清单是验收与答辩的主轴**，个性化不得删掉清单里的业务角色与主流程，只能改「怎么在板子上实现」。  
2. **小熊派决定感知/执行边界**，云端与前端补齐清单中的业务与可视化。  
3. **「可选,杜邦线」** = 清单中板载没有的能力（如开箱），允许用按键等简易器件补齐事件，而不是砍需求。  
4. Agent 仍是清单中的**一个模块**（物流智能问答），挂在应用层，不替代 GPS→MQTT→告警→调度闭环。

## 1. 老师文档：核心期望解读

### 1.1 一句话期望

做一套**面向多角色的货物运输物联网系统**：端侧采定位 → MQTT 上云 → 业务绑定与可视化 → 异常告警 → 调度指令回端侧执行；并附带物流智能问答。

### 1.2 期望拆解（比功能表更底层）

| 期望层 | 老师要什么 | 在清单中的证据 |
|--------|------------|----------------|
| **业务对象** | 「货物」与「车辆」可管理、可绑定，追踪的是运单而非裸设备 | 车辆管理、货物车辆绑定；主流程第 1 步 |
| **感知主链** | 位置必须来自硬件 GPS 采集并经 MQTT 上报 | 用户故事 1；流程「硬件GPS采集→MQTT上报」 |
| **可视与追溯** | 实时位置 + 历史轨迹（地图）+ ETA | 故事 1–3；主流程 4–6 |
| **异常闭环** | 偏航 / 异常停留 / 异常开箱 → 通知 → 地图查看 → 调度 → 解决 | 故事 4；异常处理全流程 |
| **控制闭环** | 调度指令经 MQTT 下到硬件并执行 | 故事「调度指令下发」；异常流程第 5–6 步 |
| **状态协同** | 司机上报装货/运输中/已送达，货主可感知进度 | 故事「货物状态上报」；主流程收货 |
| **多车视角** | 调度员能看车辆分布总览 | 故事「车辆分布总览」 |
| **运维追溯** | 告警日志可查 | 故事「告警日志查看」 |
| **智能模块** | 货主可对话咨询物流问题（RAG） | 故事「物流智能问答」 |

### 1.3 老师默认的两条「必讲业务流程」

必须能按文档演示（可简化 UI，不可缺步骤语义）：

**A. 货物运输全程追踪**  
绑定 → GPS 定位上报 → 货主看位置 → 轨迹 → ETA → 确认收货  

**B. 运输异常告警处理**  
监测异常 → 告警通知 → 地图看详情 → 下发调度指令 → 司机/设备侧响应 → 告警关闭  

### 1.4 角色期望（五个都要在系统中有入口或可切换角色）

货主 / 仓库管理员 / 调度员 / 司机 / 系统管理员 —— MVP 可用同一 Web 的角色切换，但**权限与菜单要能对应清单**，避免只做一个「大屏用户」。

## 2. 小熊派 + E53-ST1：能力与缺口

### 2.1 板载能力（官方 ST1）

| 部件 | 能力 | 直接支撑的老师需求 |
|------|------|--------------------|
| L80-R GPS（UART） | 经纬度；**室内通常无定位，需室外或开阔处** | 货物位置追踪、轨迹点来源 |
| 无源蜂鸣器 | 声光提示 | 调度指令「硬件接收执行」的可感知反馈 |
| LED | 状态指示 | 定位成功/指令到达/告警态指示 |
| BearPi 联网 | MQTT 上下行（视具体板型 Wi‑Fi/蜂窝方案） | 上报与指令下发通道 |

官方示例语义：读 GPS →（定位成功时）LED/蜂鸣提示；**ST1 本身没有开箱检测、没有电子锁、没有多车硬件。**

### 2.2 缺口与「杜邦线」补齐策略

| 老师需求 | 板载？ | 个性化实现 |
|----------|--------|------------|
| GPS 位置 | ✅ | 优先真 GPS；室内答辩用「模拟定位源」开关，接口与真 GPS 同一上报格式 |
| 偏航 / 异常停留 | ❌ 规则在云端 | 云端根据轨迹点计算；演示可注入偏离点 |
| 异常开箱 | ❌ | **杜邦线按键 / 磁簧** → 上报 `UNSEAL` 事件（对齐文件名「可选,杜邦线」） |
| 调度指令执行 | ✅ 蜂鸣+LED | 下行命令点亮/鸣叫/LCD 文本；ack 回云 |
| 多车辆分布 | ❌ 单板 | 1 台真机 + N 路软件模拟车（同 topic 规范） |
| 地图 | ❌ | Web 地图 SDK 或校园底图；与板无关 |
| ETA / 绑定 / 日志 / Agent | ❌ | 纯云端与应用实现 |

### 2.3 硬件约束对设计的硬影响

1. **答辩环境：** 教室演示默认准备「模拟 GPS」；室外录一段真 GPS 轨迹作加分视频。  
2. **开箱：** 不做等于清单缺项；应用杜邦线做成事件，成本低、对得上老师表述。  
3. **执行器只有蜂鸣/LED：** 「调整运输路线」在端侧体现为**指令到达与提示**，路线重算在云端/调度员侧，不强行要求板子算路。  
4. **不要幻想 ST1 有温湿度/轴感**（那是别的 E53）；个性化不加无关传感器，除非另有扩展板。

## 4. 个性化总体方案

### 4.1 产品定位（对齐老师，落在板子上）

**实训版智慧物流监控与调度系统：**  
以小熊派 E53-ST1 作为「在途车辆终端」，完成老师规定的绑定、定位上报、轨迹、三类异常、调度下发与多角色协同；智能体提供物流咨询（并建议绑定当前运单数据，避免空 RAG）。

### 4.2 个性化差异点（在满足清单前提下）

| 点 | 做法 | 目的 |
|----|------|------|
| 定位双模 | `source=gps \| sim`，载荷字段一致 | 教室可重复演示，仍尊重「硬件 GPS 采集」主叙事 |
| 开箱杜邦线 | GPIO 按键 → MQTT event | 完整覆盖老师三类异常 |
| 指令可观测 | 下行 → 蜂鸣模式区分（偏航提示/调度提醒）→ ack | 把「硬件接收执行」做实 |
| 多车 1+N | 真 ST1 + 模拟器 | 满足分布总览，不堆硬件 |
| Agent | RAG + **当前运单/告警摘要** | 满足清单问答，又贴物联网数据 |

### 4.3 端侧软件职责（BearPi）

```
循环:
  读 GPS（无效则若开启 sim 则用本地轨迹生成器）
  读开箱 GPIO
  组包 telemetry / event → MQTT publish
  订阅 command → 驱动蜂鸣/LED → publish ack
  心跳
```

不做：复杂路径规划、本地偏航大算法（可把轻量阈值放端侧，**主判定放云端**以便改阈值、写日志）。

### 4.4 云端职责

设备与车辆档案、运单绑定、轨迹入库、ETA、三类告警规则、指令与 ack、告警日志、（可选）Agent 检索与上下文组装。

## 5. 核心功能设计（按老师模块重写）

### 5.1 数据监测 — 货物位置追踪

- **老师流程：** GPS → MQTT → 后端 → 前端。  
- **设计：** 运单绑定车辆后，展示该车设备最新点；状态取自司机上报状态机。  
- **板端：** `lon, lat, fix, ts, source`。

### 5.2 数据可视化 — ETA / 轨迹 / 车辆分布

- **ETA：** 起终点已知时，用剩余直线距离 / 设定均速，或「参考路线剩余点×采样周期」；不接商业路况。  
- **轨迹：** 存储周期点；地图回放。无 Key 时用 Leaflet + 公开底图或校区示意图，但**交互仍是地图形态**（对齐「以地图形式」）。  
- **分布总览：** 调度员页聚合所有在线车辆最后点（含模拟车）。

### 5.3 告警管理 — 三类异常 + 日志

| 类型 | 检测位置 | 演示方法 |
|------|----------|----------|
| 偏航 | 云端：点到参考路线距离 > 阈值 | 真偏离或「注入偏航坐标」 |
| 异常停留 | 云端：位移 < ε 持续 > T | 设备静止或暂停 sim |
| 异常开箱 | 端侧按键上升沿 | 杜邦线按键 |
| 日志 | 云端列表 | 筛选运单/类型/时间 |

告警后通知：Web 角标/列表即可（短信作 Won't，除非课程强制）。

### 5.4 系统管理 — 车辆 / 绑定

- 车辆：编号、绑定 `deviceId`、解绑。  
- 货物：创建运单 → 选车绑定 → 设起点终点（及可选参考折线）。  

### 5.5 设备控制 — 调度指令

- 前端下发：如 `NOTIFY_RETURN_ROUTE` / `BUZZ` / `SHOW_MSG`。  
- 板端：蜂鸣模式 + LED；上报 `commandId, result=ok`。  
- 语义对齐老师「向司机/车辆下发路线调整指令」：云端可存建议路线说明，端侧负责触达。

### 5.6 数据上报 — 司机状态

- 状态：`LOADED | IN_TRANSIT | DELIVERED`（对应已装货、运输中、已送达）。  
- 入口：司机角色页；无独立 App。  
- 驱动主流程「确认收货」：货主确认或司机送达均可，需在 PRD 里定一个主操作者（建议司机送达 + 货主可确认）。

### 5.7 智能体 — 物流智能问答（模块）

- **清单原文：** 用户提问 → RAG 知识库 → 回答。  
- **个性化增强（仍算该模块）：** 回答时附加只读工具/上下文：`当前运单状态、最新位置、ETA、最近告警`。  
- **不做：** Agent 自动连发调度指令；主演示不依赖大模型在线。

## 6. 业务流程（严格贴老师两表）

### 6.1 全程追踪（实现要点）

| 步骤 | 老师动作 | 我们的实现要点 |
|------|----------|----------------|
| 1 | 绑定货物与车辆 | 仓管：运单 ↔ 车辆 ↔ device |
| 2 | 硬件 GPS 采集 | ST1 读 L80-R；室内切 sim |
| 3 | MQTT 上报 | telemetry topic |
| 4 | 货主看位置 | 运单详情实时点 |
| 5 | 轨迹 | track 查询 + 地图 |
| 6 | ETA | 后端计算字段 |
| 7 | 确认收货 | 状态 → DELIVERED，停止在途告警 |

### 6.2 异常处理（实现要点）

| 步骤 | 老师动作 | 我们的实现要点 |
|------|----------|----------------|
| 1 | 监测偏航/停留/开箱 | 规则引擎 + GPIO |
| 2–3 | 告警与通知 | 写 alert + Web 提示货主/调度 |
| 4 | 地图看异常位置 | 告警关联坐标 |
| 5 | 下发指令 | MQTT command |
| 6 | 执行 | 蜂鸣/LED；司机可同时改状态 |
| 7 | 解决关闭 | 自动（条件恢复）或手动关闭 |

## 8. MVP 定义（在「覆盖老师清单」前提下的最小可演示集）

**一次连招演示（对齐双流程）：**

1. 仓管绑定运单与车辆  
2. 设备上报位置（gps 或 sim）→ 货主看见位置与 ETA  
3. 拉出轨迹  
4. 触发偏航或开箱 → 告警列表  
5. 调度员下发指令 → 板子蜂鸣/LED → ack  
6. 司机点「已送达」  
7. （加分）货主问 Agent：「这单现在什么情况？」

多车总览：预置 2 辆模拟车 + 1 辆真机即可算覆盖。

## 9. 明确 Won't（不与老师清单冲突的裁剪）

- 短信/App 推送通道  
- 商业级路径规划与路况 ETA  
- 真车电子锁（用杜邦事件代替）  
- 独立司机原生 App  
- 以 Agent 为系统中心

## 10. 风险（紧扣板子）

| 风险 | 对老师期望的影响 | 对策 |
|------|------------------|------|
| 室内无 GPS | 主链「硬件 GPS」难现场秀 | 双模定位 + 室外补录 |
| 无开箱器件 | 三类异常缺一 | 杜邦线必做或老师确认可软模拟 |
| 地图 Key | 「地图形式」打折 | 尽早定 Leaflet/高德其一 |
| 只做单用户大屏 | 五角色期望落空 | 角色切换 + 菜单对齐 |

## 11. 核心功能锁定（对外表述）

在**完整响应老师 11 条用户故事**的前提下，工程落地为：

1. 车辆管理与货物—车辆—设备绑定  
2. GPS（及同构模拟）位置上报与货主实时监控  
3. 轨迹回放与调度员车辆分布  
4. ETA  
5. 偏航、异常停留、异常开箱告警与告警日志  
6. 调度指令 MQTT 下发与蜂鸣/LED 执行反馈  
7. 司机货物状态上报与收货闭环  
8. 物流智能问答（RAG，建议叠加运单上下文）  

其中 1–7 构成物联网主链；8 为清单规定的智能模块。个性化 = **ST1 能力内的双模定位、杜邦开箱、指令可观测、1+N 多车**，而不是另起炉灶换题。
