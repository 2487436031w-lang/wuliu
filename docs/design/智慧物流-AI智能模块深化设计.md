# 智慧物流 — AI 智能模块深化设计

> **基础版保留：** [`智慧物流-概念设计-基础版.md`](智慧物流-概念设计-基础版.md)（与当前主文档同源归档，勿覆盖）  
> **主文档：** [`智慧物流-概念设计.md`](智慧物流-概念设计.md)（物联网主链不变）  
> **本文目标：** 在老师清单「物流智能问答」之上，把 AI 嵌进**异常研判 → 调度决策 → 运单叙事**主链路，避免「侧边栏聊天 / 百科 RAG」式浮层。

---

## 1. 问题：什么叫「浮于表面」

| 浮层用法 | 为什么虚 |
|----------|----------|
| 独立聊天页问「物流是什么」 | 与 GPS/告警/指令无数据耦合 |
| 仅把运单 JSON 塞进 Prompt 再闲聊 | 无结构化产出，不进入业务状态 |
| AI 挂了演示仍完全一样 | 说明 AI 不在关键路径上 |

**深入核心的判据（满足 ≥2 条才算嵌入）：**

1. AI 由**物联网事件自动触发**（告警产生、状态变更、指令前后），而非只等人提问  
2. AI 产出**结构化结果**写入业务库（研判单、建议指令、运单摘要），可查询、可审计  
3. AI 建议能经人确认后**变成 MQTT 指令或告警定级变更**  
4. 去掉聊天 UI，调度员/货主仍能在告警详情、运单页看到 AI 产物  

物联网主链仍是：感知 → MQTT → 规则告警 → 控制。AI 是主链上的**认知层**，不是另一个 App。

---

## 2. 分层架构：规则负责「发生」，AI 负责「意味着什么、怎么办」

```
端侧 ST1: GPS / 开箱 / 蜂鸣 ack
        │ MQTT
        ▼
【确定层】规则引擎：偏航阈值、停留时长、开箱边沿 → 原始告警 Alert(raw)
        │ 事件总线 / 领域事件
        ▼
【认知层】Logistics Intelligence Module（LIM）
        ├─ ① 告警研判 Agent   Alert → Judgment
        ├─ ② 调度副驾 Agent   Judgment → CommandDraft（待确认）
        ├─ ③ 运单叙事 Agent   Shipment+Tracks+Alerts → Narrative
        └─ ④ 对话 Agent       复用①②③工具，满足老师「智能问答」
        │
        ▼
【执行层】人确认 → 原有 Command 服务 → MQTT → 蜂鸣/LED
```

- **确定层不可被 LLM 替代：** 阈值越限必须告警，保证可演示、可追责。  
- **认知层可降级：** LLM 超时则只展示规则告警（系统仍可用）；有结果则体验明显更好——这才是「更深」而不是「更脆」。

## 3. 三个深入核心的能力（建议作为 AI 的真正产品形态）

### 3.1 告警研判（Event → Judgment）—— 嵌在异常流程第 1–2 步之间

老师流程：监测异常 → 触发告警 → 通知…  

**深化：** 原始告警落地后异步调用研判，告警卡片上直接显示「智能研判」，而不是让用户去聊天框问「这是什么意思」。

**输入（工具/上下文，全部来自已有 IoT 数据）：**

- 告警类型、时间、坐标  
- 近 N 个轨迹点、参考路线偏离距离、停留时长  
- 是否同时段开箱、当前运单状态、历史同类告警次数  

**结构化输出（写入 `alert_judgment` 表）：**

```json
{
  "alertId": "...",
  "severity": "DEVIATION_LIKELY_REROUTE | DWELL_TRAFFIC_OR_REST | UNSEAL_RISK | MULTI_SIGNAL_COMPOUND | UNKNOWN",
  "severity": "P2",
  "summary": "车辆偏离参考路线约 180m，近 5 分钟无开箱事件，更像绕行而非盗抢。",
  "evidence": ["deviation_m=180", "unseal=false", "speed≈0"],
  "recommendActions": ["NOTIFY_RETURN_ROUTE", "CONTACT_DRIVER"],
  "confidence": 0.78
}
```

**为何算核心：** 异常闭环里「通知」的内容从「发生了偏航」升级为「偏航 + 解释 + 建议动作」；调度员地图详情页的第一屏就是研判，不是聊天气泡。

### 3.2 调度副驾（Judgment → CommandDraft）—— 嵌在异常流程第 5 步

老师：调度员下发指令 → 硬件执行。  

**深化：** 一键「采纳智能建议」生成指令草稿（类型、文案、目标设备），**必须人工确认**再走原 MQTT 下发；确认后把 `judgmentId` 记到 `command` 上，形成 AI→人→端 的审计链。

| 建议动作 | 映射到原系统 |
|----------|----------------|
| NOTIFY_RETURN_ROUTE | command + 蜂鸣模式 A |
| BUZZ_URGENT | 急促蜂鸣（如开箱高危） |
| MARK_WATCH | 仅提高前端关注级，不下发 |
| REQUEST_STATUS | 提醒司机上报状态（Web 侧） |

**为何算核心：** AI 进入控制闭环的「决策辅助位」，仍不绕过物联网执行通道。

### 3.3 运单叙事（Trip Narrative）—— 嵌在货主「看进度」主路径

老师：货主看位置、轨迹、ETA。  

**深化：** 运单页固定模块「本单智能速览」（定时或关键事件刷新），自动生成：

- 当前阶段一句话  
- ETA 是否可信（依据：是否偏航中、停留中）  
- 未关闭告警摘要  
- 对货主的下一步建议（准备接货 / 等待调度处理）  

对话问答变为：**同一套 Narrative/Judgment API 的交互入口**，老师要求的 RAG 放在「制度/操作说明」检索，与运单事实问答分流（见 §5）。

**为何算核心：** 货主主界面消费 AI，而不是「另开智能体菜单」。

## 4. 与基础版功能的关系（不推翻 1–7）

| 基础版物联网能力 | AI 深化后的关系 |
|------------------|-----------------|
| 规则告警 | 上游；AI 消费 Alert |
| 轨迹 / ETA / 绑定 | AI 只读上下文 |
| 调度指令 + ack | AI 只产草稿；执行仍走原服务 |
| 告警日志 | 扩展字段：研判结论、是否采纳建议 |
| 原「智能问答」 | 降为 LIM 的④号入口，背后调用研判/叙事工具 |

基础版 §9「不以 Agent 为系统中心」仍然成立：**中心仍是设备与规则**；变的是 AI 从旁路聊天变为认知层。

## 5. 满足老师「RAG 智能问答」且不流于表面

拆成两条检索/推理通道：

| 通道 | 问题类型 | 机制 |
|------|----------|------|
| **事实通道** | 「这单到哪了」「为何告警」 | 工具调用：shipment/alert/judgment/narrative API，禁止瞎编坐标 |
| **知识通道** | 「偏航一般如何处理」「绑定流程」 | RAG 手册/课程知识库 |

路由：意图分类（规则或小模型）→ 事实 / 知识 / 混合。  
混合例：「为什么告警、我该怎么办」= Judgment.summary + RAG 处置规范。

这样既对得上清单里的「RAG 知识库检索」，又把深度放在事实通道与事件触发上。

## 6. 推荐落地的「最小深入」MVP（AI 部分）

在基础版物联网 MVP 已通的前提下，AI 最小深入集：

| 优先级 | 项 | 演示怎么讲 |
|--------|----|------------|
| P0 | 告警自动研判 + 详情页展示 | 触发偏航 → 卡片出现解释与证据 |
| P0 | 采纳建议 → 填指令 → 确认下发 → 蜂鸣 | 完整「认知→执行」 |
| P1 | 运单智能速览 | 货主页一眼看懂 |
| P1 | 对话复用同一工具 | 满足清单问答，30 秒带过 |
| P2 | 多信号复合研判（偏航+开箱） | 创新点加深 |
| P2 | 研判写入告警日志可筛选 | 运维角色 |

**刻意不做（易空心或失控）：**

- LLM 直接自动下发 MQTT（无确认）  
- 用模型代替阈值检测  
- 只有知识库闲聊

## 7. 数据与接口（概念）

新增实体：

- `AlertJudgment`：见 §3.1  
- `CommandDraft`：建议指令、来源 judgmentId、状态 draft/accepted/discarded  
- `ShipmentNarrative`：运单 ID、文本、更新时间、触发原因（alert|status|schedule）

关键事件：

`AlertCreated` → 研判任务  
`JudgmentReady` → 推送调度员 UI  
`CommandDraftAccepted` → 创建正式 Command（原服务）  
`ShipmentStatusChanged` / `AlertCreated` → 刷新 Narrative  

降级：研判失败标记 `judgmentStatus=failed`，UI 回退纯规则告警。

---

## 8. 答辩怎么讲「更深」

1. 物联网确定层：GPS/开箱 → 规则 → 告警（可信、可复现）  
2. 认知层：对告警做研判，输出结构化结论与建议  
3. 人机共驾：采纳建议后走原 MQTT 控制闭环，设备蜂鸣 ack  
4. 货主侧叙事与问答共用同一智能模块，不是贴了个 ChatGPT  

一句话：**规则负责发现异常，AI 负责解释与辅助处置，设备负责执行。**

## 9. 对主文档的修订建议（尚未改基础结论时）

可将主文档 §5.7 / §11 第 8 条升级表述为：

> 物流智能模块（LIM）：事件驱动的告警研判、调度建议草稿、运单叙事；对话为统一入口；RAG 承担知识通道。

物联网 Must 条目不变；AI 从「Should 薄实现」提升为 **Should/Must（若评分强调智能体）的深入模块**，但仍可降级。
